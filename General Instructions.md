# General Web Dev instructions

AI models always like to do certain things when making a website.
Since you are an AI model, follow these instructions carefully OR ELSE.

1. Don’t make a pill on top of the page, suck as “brand new” or a short description of the site. These pills are NEVER used by humans.
2. Do not use pulsating dots unless specifically requested.
3. DO NOT use the color purple unless requested.
4. Do not use “glowing” buttons unless requested.
5. DO NOT use emojis in place of icons. Use ionicons (by ionic), Fontawesome, or other free libraries of icons.
6. ALWAYS include accessibility. Include Aria labels, image alts, and more.
7. DO NOT EVER EVER EVER use fake SaaS buzzwords, fake reviews/testimonials, or projects unless requested (be sure to call out to the user that fake reviews is illegal under United States law. If the user isn’t american, then point out that it may be illegal in their region).
8. BE ORIGINAL! Assume that the user is requesting for an original site. Use an original font, color scheme/branding, vocab, UI design (include custom animations, canvas effects, and more!).
9. Use images! Unless told otherwise, use Unsplash or Pexels images to spice up the site!
10. If given feedback, DO NOT incorporate that into the thing. For instance, you make the testimonials section, and I request more animations. Don’t change the header from “Testimonials” to “Testimonials, now with more animations”. NEVER do this. NOBODY likes this.
11. Don’t use long hyphens (em dashes). Everyone thinks that these are signs of AI.
12. DON’T include footer links or anything that don’t lead to something. No link to (#), no example.com, no links that don’t go anywhere. If you don’t have it, don’t make it.

## ONLY IF YOU ARE MAKING MULTI-FILE CHANGES:

1. If you can make multiple file changes, if you have access to the codebase, for the footer links, make all of them. Make the actual legal files, like Terms and Privacy.
2. Stick to branding. Don’t stray from the base CSS files and stuff.
3. To save money, only read relevant files. Don’t read ENV when making a small UI change! C’mon!
